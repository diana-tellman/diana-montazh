# Референс → разбор по кадрам

Цель — повторить **схему** референса (последовательность, ритм, композицию, приёмы, типографику, цвет), а не его содержание. Голос, лицо, смысл — пользователя. Явные слова пользователя важнее референса. Референс прошлого проекта не переносится.

## Видео-референс
0. **Исследование «по молекулам»:** `npm run study -- <ref.mp4> --out projects/<id>/work/study-ref` → `study.md` (склейки и длина планов, темп, пики движения, громкость, паузы, есть ли музыка, звуковые удары/SFX и совпадают ли они со склейками), `shots.jpg` (кадр каждого плана), `timeline.png` (дорожки). Посмотри оба изображения сам. Для своего исходника то же с `--transcript work/transcript.json` (скорость речи, паузы). Ограничения: удары в речевом видео часто — согласные звуки, а не SFX; музыку под голосом определяем по уровню в паузах — это оценка.
1. Проект с материалами пользователя (без референса): `npm run new …`.
2. `npm run reference -- <id> <ref.mp4>` → цвет (LUT `work/reference/grade.cube`), темп (склеек/с → энергия камеры), громкость, лист кадров `work/reference/frames.jpg`.
3. Посмотри `frames.jpg` (и при нужде отдельные кадры `ffmpeg -ss <t> -frames:v 1`). Составь **таблицу разбора**:

| # | Время в референсе | Композиция / план | Камера | Анимация / переход | Текст (место, шрифт, размер, анимация) | Звук | → Где в новом ролике (по смыслу речи) |
|---|---|---|---|---|---|---|---|

   Переносить на **моменты речи с тем же смыслом**, а не на те же секунды.
   Затем **разложи референс по дорожкам** (как в монтажке) — это и есть «стиль по молекулам»:
   | Дорожка | Что записать из референса |
   |---|---|
   | V1 камера/видео | планы и их длина, крупность, наезды (cut/плавно, %), ч/б, цвет |
   | V2 фон | замена фона, фактура, панели, свет |
   | V3 текст за человеком | слово, шрифт-класс, размер (доля ширины), цвет, анимация |
   | V4 силуэт | контур, вырезание |
   | V5 текст/графика спереди | роли строк (маленькая/огромная/курсив/рукопись), позиция, анимация, выход |
   | V6 переходы | тип (whip, панель со словом, вспышка, маска), длительность |
   | T субтитры | сколько слов, где, стиль, есть ли вообще |
   | A1 голос / A2 музыка / A3 SFX | громкость, музыка под голосом (дакинг), какие удары на каких движениях, частота |
   Перенеси это в `showcase.json` (`editorial-style.md`) или в опции `plan`.
4. Заполни `storyboard/reference-style.json` по видимому (неуверен → `null`): `font` (modern-sans | neutral-sans | geometric-bold | serif | condensed | rounded | rounded-bold | elegant | tight-display | soft-geometric | editorial-serif | script), `weight`, `uppercase`, `size`, `textColor`, `accentColor`, `onAccent`, `position`, `wordsPerPhrase` 1–6, `activeWord` (pill|color|scale|underline), `upcoming`, `backdrop` (shadow|glass|none), `animation` (pop|rise|fade|slide), `behindText`, `icons`, `progressBar`, `sfx`, `layout`, `grade`, `gradeStrength`, `notes`. Звук референса ты не слышишь → про звук `null`, если пользователь не сказал.
5. Приёмы (окна, экран на два, схемы, плашки, частота) → `storyboard/directions.json` (`meaning-to-frame.md`). Нет приёмов → `--no-semantic`.
6. `npm run plan -- <id> --reference [явные пожелания: --font, --accent, --text, --size, --upper|--lower…]`.
7. При показе раскадровки скажи: что взято из референса, что — по словам пользователя, что повторить нельзя и почему (точный шрифт может отличаться — ближайший с казахскими буквами; эффект, для которого нет материала).

## Сайт или презентация как референс
Попроси скриншоты/PDF (страницы сайтов из облака часто не открываются). Разбери: структура блоков, сетка и отступы, типографика (иерархия, кегли, начертания), палитра (HEX по скриншоту), форма элементов (скругления, тени, стекло), как появляются элементы. Перенеси в `reference-style.json` / опции стиля / `directions.json` и покажи ту же таблицу «что → где».

## Если часть не видна или не хватает материала
Не угадывай молча: одним вопросом с 2 вариантами («референсте мұнда қол көрінеді, сенде ондай кадр жоқ: а) фото жібересің б) осы жерге схема қоям ⭐»).
