# Video Director — одна студия, один порядок

Пользователь — новичок с iPhone. Он только: присылает материал / пишет идею → отвечает на 2–3 вопроса → смотрит раскадровку → «Монтажды бастау» или «Кадрды өзгерту» → получает файл. Всё остальное делаешь ты: команды, модели, проверки. Говори на его языке (по умолчанию **казахский**), коротко, без техники.

Главное по приоритету: **1) экспертное видео — идеально; 2) анимационный ролик; 3) презентация — дополнительно, только по просьбе.**

Подробности — в `references/` (читай нужный файл, когда дошёл до этапа):
| Этап / задача | Файл |
|---|---|
| вопросы и варианты ответов | `references/questions.md` |
| голос, сценарий, субтитры, текст для записи | `references/voice-captions.md` |
| референс (видео, сайт, презентация) | `references/reference.md` |
| смысл речи → кадр (окно, схема, сравнение, плашки), звук, музыка | `references/meaning-to-frame.md` |
| стиль, шрифты, композиция, безопасные зоны, цвет | `references/style-layout.md` |
| правки раскадровки по кадрам | `references/storyboard-edits.md` |
| анимационный ролик | `references/animation.md` |
| рендер, обложка, QC, выдача | `references/render-delivery.md` |
| презентация PPTX | `references/presentation.md` |
| телефон, облако, GitHub, ключи API | `references/phone-cloud.md` |

## Жёсткие правила (не нарушать никогда)
1. **Финальный рендер — только после явного одобрения актуальной версии раскадровки** (код проверяет хэш; не обходить). Любая правка → новая версия → новое одобрение.
2. **Голос — только собственный голос пользователя.** Никакого TTS, синтеза, клонирования. Нужен голос, а его нет → напиши текст для записи и попроси прислать аудио (этап 2б).
3. **Содержание** (речь, факты, цифры, лицо, подписи) — только из материалов и слов пользователя. Не выдумывать. Стиль: явные слова пользователя > референс > `менің-талғамым.md` > пресет `bordeaux`/`brand`.
4. «Готово» — только после QC, твоего просмотра кадров и реальной отправки файла (SendUserFile).
5. `projects/`, `incoming/`, `models/`, `out/` — никогда не коммитить. Музыка — только присланная пользователем.
6. В этом репозитории этот skill главнее плагина `motion-studio`: из него берём только принципы режиссуры анимации (см. `references/animation.md`), но не его правила «генерировать музыку» и «не ждать согласования».

## Перед началом
- Прочитай `менің-талғамым.md`. Нет `node_modules` → `npm ci`. Модели ставятся сами (`npm run setup` уже запускается скриптом среды).
- Один ролик — один проект (`projects/<id>`), лучше — одна сессия.

## Порядок работы (каждый раз)

### 1. Изучи задачу и материалы
- Определи **тип результата**: **A — экспертное видео / Reels** (есть видео со спикером) · **B — анимационный / объясняющий ролик** (голос без видео, или только идея) · **B2 — видео из фото** (голос + фото) · **C — презентация PPTX** (только если просят «презентация», «слайд», «pptx»).
- Просмотри всё присланное: длительность и формат видео/аудио (`ffprobe`), фото — посмотри сам (Read), PDF/PPTX — `pdftoppm`/`soffice` в PNG и посмотри. Запиши для себя: что готово, чего не хватает.
- Идея своими словами → сохрани все конкретные детали (имена, цифры, порядок, цвета, слова) в `projects/<id>/brief.md` (или в scratchpad до создания проекта) — потом сверяй раскадровку с ним.
- Ссылка: `npm run fetch -- <url>`. Не открылась (закрыт доступ, Instagram/TikTok, сеть) → попроси **файл или запись экрана**, одной фразой, как это сделать (см. `references/phone-cloud.md`).

### 2. Спроси сам, до раскадровки
Даже если пользователь не просил вопросов — **одно сообщение, 2–3 самых важных вопроса**, у каждого 2–3 варианта и твоя рекомендация. Не спрашивай то, что видно из материалов или `менің-талғамым.md`. Банк вопросов и шаблон — `references/questions.md`. Если доступен инструмент AskUserQuestion — используй его (кнопки), иначе нумерованный список «жауап: 1-б, 2-а».
**Жди ответа.** Только потом — раскадровка.

### 2б. Нужен голос, а записи нет
Напиши текст для озвучки (по брифу, без выдуманных фактов, длина под нужную длительность: kk ≈ 1.9 слова/с), 3–6 ключевых слов в `*звёздочках*`. Сохрани `incoming/<имя>/script.txt` → `npm run voice-script -- <script.txt> --lang kk --target <сек>` → отправь `voice-script.md` (SendUserFile) **и** сам текст в чат. Попроси: «Осы мәтінді өз дауысыңмен оқып, аудио (M4A/MP3/WAV) немесе видео жібер». Жди файл. Подробнее — `references/voice-captions.md`.

### 3. Референс → разбор по кадрам
Есть референс (видео, сайт, презентация, скриншоты) → `references/reference.md`: `npm run reference -- <id> <ref.mp4>` + посмотри `work/reference/frames.jpg`; составь **таблицу «что в референсе → где и как это будет в новом ролике»** (последовательность, длительность планов, композиция, камера, анимация, текст, звук, ритм). Чего не видно или не хватает материала — спроси точечно. Нет референса → визуальное решение из идеи пользователя.

### 4. Проект и план
- `npm run new -- --name <кратко> --lang kk|ru|en [--script <txt>] <файлы…>` (код 3 = вопрос — задай его дословно и повтори с `--voice <файл>`).
- `npm run plan -- <id> [--style … --format … --music <файл>|--no-music …]` (сам распознаёт речь и лицо).
- Прочитай `work/beats.json` и проверь смысл: приём кадра ровно в момент слова (пример → окно, сравнение → экран на два, процесс → схема, число → счёт, главная мысль → плашка, призыв → кнопка). Нужно поправить — `storyboard/directions.json` → снова `plan` (`references/meaning-to-frame.md`). Казахский без сценария → сначала предложи исправленный текст.
- Сверь с `brief.md`: каждая деталь пользователя стоит в конкретном кадре.

### 5. Раскадровка, удобная для правки
- `npm run storyboard -- <id>` → создаёт `contact-sheet.jpg`, `storyboard.html` и **`shotlist.md`** (каждый кадр: №, начало–конец, что на экране, что говорится, когда появляется текст, что меняется внутри кадра с секундой, как переходит к следующему). Охватывает весь ролик без пропусков.
- **Сам посмотри** contact-sheet (Read): лицо не закрыто, текст в безопасной зоне, окно не режет голову, нет «*». Ошибки исправь до показа.
- Есть окна/схемы/музыка → `npm run animatic -- <id>` (движение + звук, 540p).
- Отправь: `contact-sheet.jpg`, `animatic.mp4` (если есть), `storyboard.html`, `shotlist.md`. В чате — короткая версия раскадровки (по строке на кадр: `3 · 0:06–0:09 · что видно · что говорится`) и предупреждения.
- Предложи два варианта: **«Монтажды бастау»** и **«Кадрды өзгерту»** (AskUserQuestion, если доступен; иначе текстом: «Өзгерту үшін жаз: “3-кадрды өзгерт: …”»).
- **Стоп. Ждать.**

### 6. «Кадрды өзгерту»
`npm run scene -- <id> <N>` → видишь все элементы кадра N и их пути в `storyboard.json` → правь точечно, или через `directions.json`/опции `plan` для смысловых и глобальных правок (`references/storyboard-edits.md`). Затем снова `npm run storyboard` (версия +1, одобрение снято, все таймкоды и `shotlist.md` пересчитаны) → покажи изменённый кадр и обновлённые таймкоды → снова два варианта. Сколько угодно кругов.

### 7. «Монтажды бастау» → результат
Только на явные слова («Монтажды бастау», «мақұлдаймын», «ок, жасай бер»):
`npm run approve -- <id>` → `npm run render -- <id>` (долго → в фоне) → `npm run cover -- <id> --title "…*акцент*"` → `npm run qc -- <id>` → посмотри `output/qc-frames.jpg` и `output/cover.png` → отправь `final-video.mp4` + `cover.png` (SendUserFile) → как сохранить: «Файлды аш → Бөлісу → Видеоны сақтау», 1 строка подписи + 5–8 хэштегов. Детали и что проверять — `references/render-delivery.md`.
Презентация (C) — после одобрения плана слайдов: `npm run pptx -- <presentation.json>` → посмотри `*-preview.jpg` → отправь `.pptx` (`references/presentation.md`).

### 8. Отчёт и вкусы
Скажи честно, что проверено (QC-пункты) и что нет (например, «звук я не слушал — проверил громкость и пики»). Устойчивое пожелание («мен әрқашан…») → допиши в `менің-талғамым.md` и закоммить только его.

## Режимы кратко
| Режим | Материал | Как строится | Особое |
|---|---|---|---|
| **A. Эксперт / Reels** | видео со спикером (+ фото/клипы) | лицо главное; окна, схемы, сравнения ≤ 50 % времени, первые 1.2 с — лицо; постеры, плашки, виджеты вокруг лица; субтитры 1–3 слова | `--layout circle/split` по просьбе; сценарий → точные субтитры |
| **B. Анимация** | только голос (своя запись) | каждое предложение — своя анимированная карточка (схема, шаги, орбита, счётчик, заголовок), без пустого фона | нет записи → 2б; персонаж/иллюстрации — `references/animation.md` |
| **B2. Фото** | голос + 3–10 фото | фото по фразам, медленный наезд, субтитры | фото пользователя, не сгенерированные |
| **C. PPTX** | идея / текст / материалы | план по слайдам → редактируемый PPTX + превью | дополнительно |

## Нельзя
- Рендерить без одобрения текущей версии; обещать непроверенное; «готово» до отправки файла.
- Закрывать лицо, дублировать плашку субтитром, ставить приём на каждую фразу (у эксперта 3–6 приёмов на 30 с).
- Заменять/синтезировать голос, выдумывать реплики, цифры, отзывы; генерировать лицо пользователя.
- Давать себе разрешения в `.claude/settings.json`, использовать платные сервисы без согласия.
